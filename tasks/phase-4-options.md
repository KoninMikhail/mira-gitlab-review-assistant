# Фаза 4 — Опциональные возможности и масштаб

**Цель фазы:** расширения поверх стабильного прод-сервиса. Все задачи —
**опциональны** и берутся по потребности; ни одна не обязательна для рабочего бота.
**Критерий выхода фазы:** по каждой выбранной опции — измеримая польза без регресса
качества/безопасности.

Связанные документы: [03-implementation-options](../docs/04-architecture/adr/004-review-engine-port-cli-then-sdk.md),
[06-integrations](../docs/03-reference/integrations-api.md), [09-security](../docs/05-operations/security.md),
[10-observability](../docs/05-operations/observability.md).

### T4.1 — CloudEngine (масштабирование через Cursor cloud)
- **Статус:** TODO
- **Размер:** L
- **Цель:** для отдельных проектов выносить прогон агента в Cursor cloud, разгружая сервер.
- **Зависит от:** T3.1; согласование ИБ по доступу cloud к репозиторию.
- **Шаги:**
  - [ ] Адаптер `CloudEngine` за портом `ReviewEngine`.
  - [ ] Решить вопрос доступа cloud-VM к self-hosted GitLab (сеть/зеркало/исключения).
  - [ ] Конфиг: какие проекты используют cloud-движок.
  - [ ] Оценить приватность кода (cloud сильнее выносит код за периметр).
- **DoD:** выбранные проекты ревьюятся через cloud без потери качества; ИБ согласовано.
- **Ссылки:** [03](../docs/04-architecture/adr/004-review-engine-port-cli-then-sdk.md) (C).

### T4.2 — Auto-fix (предложение патчей) — gated
- **Статус:** TODO
- **Размер:** L
- **Цель:** бот предлагает исправления (патч/коммит/новый MR), а не только комментарии.
- **Зависит от:** стабильная Фаза 3; **явное решение** изменить scope (сейчас Q-4 = только комментарии).
- **Шаги:**
  - [ ] Жёсткие ограничения: отдельная ветка, без пуша в ветку MR напрямую, без merge/approve.
  - [ ] Изоляция прав bot-аккаунта для записи кода (отдельно от комментариев).
  - [ ] Генерация патча агентом + ревью патча человеком обязательно.
  - [ ] Защита от prompt injection усилена (агент не исполняет инструкции из кода).
  - [ ] Метрики принятия авто-патчей.
- **DoD:** авто-патчи появляются только как предложение, требуют человеческого подтверждения, безопасны.
- **Ссылки:** [00](../docs/01-concepts/overview.md) (N2), [09](../docs/05-operations/security.md) §4–§5.

### T4.3 — GitLab write-MCP (W1) — унификация
- **Статус:** TODO
- **Размер:** M
- **Цель:** при желании унифицировать запись через MCP вместо прямого REST.
- **Зависит от:** T2.2 (REST writer как baseline).
- **Шаги:**
  - [ ] Разработать/расширить GitLab MCP инструментами write (заметки, дискуссии, резолв).
  - [ ] Если делаем — вынести как отдельный пакет (переход к multi-package monorepo, [13](../docs/04-architecture/adr/003-modular-monolith-roles.md) §6).
  - [ ] Сохранить принцип «публикует Publisher, не агент».
- **DoD:** Publisher может писать через MCP; REST остаётся как fallback.
- **Ссылки:** [06](../docs/03-reference/integrations-api.md) §3 (W1), [13](../docs/04-architecture/adr/003-modular-monolith-roles.md) §6.

### T4.4 — Дашборд/Canvas активных ревью
- **Статус:** TODO
- **Размер:** M
- **Цель:** визуализация активных ревью, истории и метрик качества для тимлида.
- **Зависит от:** T3.7 (Postgres, метрики).
- **Шаги:**
  - [ ] Источник — state store (история ревью, находки, метрики).
  - [ ] Панели: активные прогоны, реплеи, accepted/dismissed, coverage по командам.
  - [ ] Рассмотреть Cursor Canvas как лёгкий способ рендера поверх данных.
- **DoD:** тимлид видит состояние и пользу бота в одном месте.
- **Ссылки:** [10](../docs/05-operations/observability.md) §7.

## Итог фазы 4
Набор опциональных усилений: облачный движок для масштаба, auto-fix (по отдельному
решению), унификация записи через MCP и наглядный дашборд. Берутся по мере
потребности, базовый сервис в них не нуждается.
