## Формат задачи

```
### T<phase>.<n> — Название
- **Статус:** TODO | DOING | BLOCKED | DONE
- **Размер:** S | M | L
- **Цель:** зачем задача, какой результат
- **Зависит от:** T..., внешние предусловия
- **Артефакты:** что появляется в коде/инфре
- **Шаги:** детальный чек-лист
- **Критерии приёмки (DoD):** проверяемые условия завершения
- **Ссылки:** разделы docs
```

## Легенда статусов

- **TODO** — не начато.
- **DOING** — в работе (один-два пункта одновременно).
- **BLOCKED** — ждёт внешнего решения/доступа (указать что).
- **DONE** — выполнено, DoD закрыт.

## Зафиксированные решения (контекст для всех задач)

Не пересматриваются без явного решения (см. [11-roadmap](../docs/01-concepts/roadmap.md) §4):

| Аспект | Решение |
| --- | --- |
| Язык | TypeScript (`@cursor/sdk`) |
| Модель | Composer 2.5 (`composer-2.5`) |
| Движок | CLI headless (MVP) → SDK local (прод), за портом `ReviewEngine` |
| Структура | Модульный монолит, один образ, роли `api`/`worker` ([13](../docs/04-architecture/adr/003-modular-monolith-roles.md)) |
| Триггеры | Первичное состояние MR (`open`/`ready`) + `@mira review`; не на каждый пуш |
| Enrollment | По членству bot-аккаунта в GitLab |
| Запись в GitLab | REST под выделенным bot-аккаунтом |
| Связь MR↔Kaiten | ID карточки в ветке + ссылка в описании MR |
| Egress на Cursor API | Разрешён |
| Scope | Только консультативные комментарии (без auto-fix) |

## Предусловия проекта (организационные, вне кода)

Эти пункты заводятся параллельно Фазе 0 и нужны к Фазе 2:

- [ ] Создан **GitLab-аккаунт бота** (Mira) — единый принципал для read/write/discovery.
- [ ] Боту выданы доступы к пилотным репозиториям; проверено право писать заметки в MR.
- [ ] Получен `CURSOR_API_KEY` с доступом к `composer-2.5`.
- [ ] Подтверждён сетевой доступ сервера до Cursor API / GitLab / Kaiten.
- [ ] Заведён токен Kaiten (read; write для комментариев — опционально).
