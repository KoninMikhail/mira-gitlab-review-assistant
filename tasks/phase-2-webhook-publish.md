# Фаза 2 — Webhook + публикация ревью в MR

**Цель фазы:** перейти от polling+dry-run к секундной реакции и реальной публикации
ревью в MR под bot-аккаунтом, идемпотентно. Добавить ChatOps (`@mira review`).
**Критерий выхода фазы:** на пилотных проектах бот в течение минут публикует
структурированное ревью в MR, не дублирует комментарии при повторных пушах,
отвечает на `@mira review`.

Связанные документы: [04-triggers](../docs/04-architecture/triggers.md),
[05-review-pipeline](../docs/04-architecture/review-pipeline.md), [06-integrations](../docs/03-reference/integrations-api.md),
[09-security](../docs/05-operations/security.md).

---

### T2.1 — Webhook receiver (api)
- **Статус:** TODO
- **Размер:** M
- **Цель:** принимать события GitLab и ставить задачи в очередь.
- **Зависит от:** T1.4, T1.5 (нормализация в ReviewJob).
- **Артефакты:** `entrypoints/api` (HTTP), эндпоинт webhook + `/healthz`.
- **Шаги:**
  - [ ] Принять `Merge Request Hook` и `Note Hook`.
  - [ ] Проверять `X-Gitlab-Token` (секрет); быстрый `200` после постановки в очередь.
  - [ ] Фильтрация событий по `review_on`: `open`(не draft)/`reopen`/`draft→ready`;
        игнор фиксов, лейблов, системных событий.
  - [ ] Нормализация в `ReviewJob` (тот же, что у poller).
- **DoD:** валидное событие → задача в очереди за <1с; неверный токен → отказ; шум отфильтрован.
- **Ссылки:** [04](../docs/04-architecture/triggers.md) (Вариант A), [09](../docs/05-operations/security.md) §6.

### T2.2 — GitLab REST Writer (под bot-аккаунтом)
- **Статус:** TODO
- **Размер:** M
- **Цель:** реализовать порт `VcsWriter` через GitLab REST токеном бота.
- **Зависит от:** bot-аккаунт заведён и имеет право писать заметки; T1.1.
- **Артефакты:** `adapters/vcs/gitlab` (writer).
- **Шаги:**
  - [ ] Создание дискуссии: `POST /projects/:id/merge_requests/:iid/discussions` (inline и общая).
  - [ ] Заметки: создание/редактирование `.../notes` (для сводного комментария).
  - [ ] Резолв дискуссии: `PUT .../discussions/:id?resolved=true`.
  - [ ] Обработка лимитов API (rate-limit, backoff).
- **DoD:** writer умеет создавать/обновлять/резолвить дискуссии и заметки под bot-аккаунтом.
- **Ссылки:** [06](../docs/03-reference/integrations-api.md) §3 (W2+W3).

### T2.3 — Идемпотентный Publisher для MR
- **Статус:** TODO
- **Размер:** L
- **Цель:** публиковать находки без дублей; обновлять/закрывать устаревшие.
- **Зависит от:** T2.2, T1.9 (fingerprints), T1.3 (store).
- **Артефакты:** `GitLabPublisher`.
- **Шаги:**
  - [ ] Маркеры в сообщениях: `<!-- mira:summary:mr-<iid> -->`, `<!-- mira:finding:<fp> -->`.
  - [ ] Сводный комментарий — один на MR, обновляется (edit), не плодится.
  - [ ] Inline-дискуссии для новых находок; резолв исчезнувших («исправлено»).
  - [ ] Сопоставление с прошлым состоянием из state store по fingerprint.
  - [ ] Учёт игнор-листа (`@mira ignore`).
- **DoD:** повторные пуши/ре-ревью не создают дублей; исправленные находки закрываются.
- **Ссылки:** [05](../docs/04-architecture/review-pipeline.md) §6–§7.

### T2.4 — ChatOps парсер (`@mira`)
- **Статус:** TODO
- **Размер:** S
- **Цель:** ручное управление ботом из комментариев MR.
- **Зависит от:** T2.1.
- **Артефакты:** парсер команд в `core/policy`/ingress.
- **Шаги:**
  - [ ] `@mira review` (ре-ревью актуального коммита), `@mira review --full`.
  - [ ] `@mira ignore <fingerprint>` → запись в игнор-лист MR (store).
  - [ ] Реакция/подтверждение в треде (через writer).
- **DoD:** команды распознаются и выполняются; `ignore` исключает находку из будущих публикаций.
- **Ссылки:** [04](../docs/04-architecture/triggers.md) (Вариант C), [05](../docs/04-architecture/review-pipeline.md) §6.

### T2.5 — Debounce и дедуп на ingress
- **Статус:** TODO
- **Размер:** S
- **Цель:** схлопывать серию быстрых событий в один актуальный запуск.
- **Зависит от:** T2.1, T1.4.
- **Шаги:**
  - [ ] Debounce-окно (30–60с): запуск по последнему SHA, промежуточные отменять.
  - [ ] Дедуп по `(project, mr, last_commit_sha, action)` для повторных доставок.
- **DoD:** быстрый каскад пушей → одно ревью по последнему коммиту.
- **Ссылки:** [04](../docs/04-architecture/triggers.md) (Дедуп и debounce).
