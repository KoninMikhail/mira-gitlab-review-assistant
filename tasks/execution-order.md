# Линейный порядок выполнения (шаг за шагом)

Единая сквозная последовательность всех задач из фаз 0–4, упорядоченная **по
зависимостям** (топологическая сортировка). Это «дорожка исполнения»: бери
следующий невыполненный шаг — все его предусловия уже закрыты предыдущими.

- Содержание задач **не дублируется** — здесь только порядок, размер и ключевая
  зависимость. Полное описание (цель, шаги, DoD) — в файлах фаз.
- `∥` помечает шаги, которые можно делать **параллельно** с соседними (зависимости
  не пересекаются) — порядок между ними не важен.
- 🔑 — внешнее (организационное) предусловие, не код. Список — в [README](./README.md).
- Размер: S / M / L.

> Это представление-«вид», а не новый источник правды. При изменении зависимостей
> в файлах фаз — пересобрать порядок здесь.

## Критический путь (самая длинная цепочка зависимостей)

Минимальная последовательность, которую нельзя распараллелить — определяет срок до
прод-готового бота (конец фазы 3):

```
T0.1 → T0.3 → T0.5 → T0.7 → T1.1 → T1.7 → T1.9 → T2.3 → T3.6
                                  ↘ T1.6 → T1.8 → T3.4
```

Параллельные ветки (`∥`) сокращают календарное время, но не критический путь.
Узкие места по зависимостям: **T0.1** (блокирует всё), **T1.1** (блокирует всю
фазу 1+), **T1.7** (движок — вход в качество/SDK), **T2.3** (публикация — вход в
цикл качества).
