# Project Brief — Mira Review Bot

**Mira** — автономный сервис код-ревью для Merge Request'ов в self-hosted GitLab.
Запускается на выделенном сервере, использует **Cursor** (CLI headless / SDK) как
«движок мышления» и ревьюит код **в контексте задачи Kaiten** (описание, критерии
приёмки), ища баги, регрессии, проблемы безопасности/производительности и
расхождения с требованиями.

Полный обзор и цели — [`docs/01-concepts/overview.md`](../01-concepts/overview.md).

## Что делает (в одной фразе)

Событие в MR → собрать контекст (diff + связанная карточка Kaiten) → прогнать
Cursor по юнитам → структурированные находки → опубликовать ревью обратно.

## Границы

- **Не gate:** не блокирует merge, не ставит approve, не пушит правки (auto-fix —
  опциональная поздняя фаза).
- **Не заменяет CI:** тесты/линтеры не запускает (может читать их как контекст).
- **Без GitLab CI/CD pipelines** — это отдельный сервис, не job в пайплайне.
- **Kaiten — read-only** под текущим личным токеном (см. правило
  `kaiten-read-only.mdc`). Запись в Kaiten — только через будущий сервис-аккаунт.

## Ключевые архитектурные решения (зафиксированы)

| Аспект | Решение |
| --- | --- |
| Язык | TypeScript (`@cursor/sdk`), ESM, Node ≥24 (нативный запуск `.ts`) |
| Модель | Cursor Composer 2.5 (`composer-2.5`) |
| Движок | CLI headless (MVP) → SDK local (прод), за портом `ReviewEngine` |
| Архитектура | Гексагональная: `core` (домен+порты) ← `adapters` ← `entrypoints` |
| Структура | Модульный монолит, один образ, роли `api`/`worker`/`poller`/`all` |
| VCS | self-hosted GitLab (`gitlab.ai-referent.ru`); read сейчас, write — фаза 2 |
| Трекер | Kaiten (read), связь MR↔карточка по ID в ветке/описании |
| Триггер MVP | polling по первичному состоянию MR (`open`/`ready`), не на каждый пуш |

Обоснования решений — [`docs/04-architecture/overview.md`](../04-architecture/overview.md)
и записи [`docs/04-architecture/adr/`](../04-architecture/adr/README.md).

## Текущий статус

- **Фаза 0 (PoC)** и **Фаза 1 (MVP: polling + CLI-движок + dry-run)** — код
  реализован, тесты зелёные. Publisher пока **dry-run** (только структурный лог,
  в GitLab/Kaiten не пишет).
- Блокер живых прогонов: 🔑P2 — боту не выданы доступы к пилотным репозиториям.
- **Фаза 2+** (webhook, публикация в MR под bot-аккаунтом, SDK-движок,
  устойчивость) — не начаты.

Детальный статус задач — [`tasks/execution-order.md`](../../tasks/execution-order.md)
