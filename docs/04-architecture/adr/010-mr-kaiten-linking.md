# 010. Связка MR ↔ Kaiten (ветка + описание)

- Статус: Принято (Accepted)
- Дата: 2026-06
- Контекст-ссылки: [../../03-reference/integrations-api.md](../../03-reference/integrations-api.md), [008-kaiten-read-only.md](./008-kaiten-read-only.md)

## Контекст

Ревью должно проверять **соответствие задаче** — для этого нужно надёжно сопоставить
MR с карточкой Kaiten. Ни одна эвристика не покрывает 100% случаев (вопрос **Q-2**).
В design-doc описаны четыре стратегии с приоритетами; нужна **командная конвенция**
и реализация резолвера в `core/linking/`.

## Решение

**Каноническая конвенция команды (Q-2):**

1. **ID карточки в имени ветки** — паттерн вида `feature/<cardId>-slug`
   (конфигурируемый `branch_regex`);
2. **Явная ссылка на карточку в описании или заголовке MR** — URL Kaiten,
   `KAITEN-<id>`, `#<id>` (шаблон описания MR).

**Резолвер многоступенчатый** (`src/core/linking/resolve.ts`), приоритет стратегий:

| # | Стратегия | Надёжность |
| --- | --- | --- |
| 1 | Явная ссылка в title/description | Высокая |
| 2 | ID из имени ветки (`branchRegex`) | Высокая (при соблюдении конвенции) |
| — | External link на карточке, текстовый поиск | Запланированы в design; **не в MVP-коде** |

При извлечённом ID, но ошибке `getCard` — **деградация** (`found: false` + reason),
не падение пайплайна. Если ID нигде нет — ревью **по diff без задачи** + пометка
«задача не найдена».

Дефолтный `branchRegex`: `^[^/]+\/(\d+)(?:-.*)?$` (например `feature/4567-some-slug`).

`branch_regex` и `descriptionPatterns` переопределяются в политике проекта под
фактический формат веток команды.

## Последствия

**Плюсы:**

- Детерминированная связь при соблюдении конвенции;
- резолвер в `core` — без зависимости от Kaiten API в pure-функциях извлечения ID;
- graceful degradation сохраняет ценность ревью без задачи.

**Минусы:**

- MR без ветки/описания по конвенции — слабая проверка requirements;
- external link и search требуют доработки (и для link — write в Kaiten позже).

**Включает:** `extractIdFromText`, `extractIdFromBranch`, `resolveCard`; тесты в
`test/linking.test.ts`.

## Альтернативы

| Вариант | Почему отклонён как единственный канон |
| --- | --- |
| Только поиск по заголовку MR | Ложные совпадения; низкая уверенность |
| Только external link в Kaiten | Требует write для автопроставления; не всегда заполнено |
| Ручной ввод card ID в конфиге MR | Не масштабируется; высокий операционный overhead |
| Одна стратегия без fallback | Хрупко при отклонении от идеального процесса |
