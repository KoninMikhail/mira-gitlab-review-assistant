# 011. Egress кода в Cursor API разрешён

- Статус: Принято (Accepted)
- Дата: 2026-06
- Контекст-ссылки: [../../05-operations/security.md](../../05-operations/security.md), [004-review-engine-port-cli-then-sdk.md](./004-review-engine-port-cli-then-sdk.md), [../../01-concepts/roadmap.md](../../01-concepts/roadmap.md)

## Контекст

При local-runtime (CLI headless или SDK) **код MR и промпт отправляются в Cursor API**
для работы модели. Это фундаментальный поток данных архитектуры (см. границы
доверия в design-doc). Без согласования ИБ проект был бы заблокирован: альтернатива —
self-hosted исполнение модели или другой движок без внешнего egress.

Вопрос **Q-3** требовал явного решения политики безопасности.

## Решение

**Передача исходного кода MR в Cursor API — разрешена** политикой безопасности.
Это **основа архитектуры**: local-runtime + Composer 2.5 через CLI/SDK.

Сопутствующие меры (не отменяют разрешение):

- egress firewall на сервере Mira: только Cursor API, GitLab, Kaiten;
- точечное отключение Mira для особо чувствительных репозиториев
  (`projects.<path>.enabled: false`);
- cloud-движок (код сильнее покидает периметр) — **не по умолчанию**, отдельное
  согласование;
- запасной план при изменении политики — self-hosted модель (будущая развилка,
  фаза «на потом»).

Cloud agents и усиленный egress — опция масштабирования, не MVP.

## Последствия

**Плюсы:**

- Разблокированы CLI и SDK как движки; не нужен свой LLM-стек на старте;
- Cursor Grok 4.6 Fast — зафиксированная модель с предсказуемым качеством.

**Минусы:**

- Исходный код покидает внутренний периметр (на Cursor API);
- зависимость от доступности и политики Cursor как вендора;
- при ужесточении ИБ потребуется миграция на self-hosted или смена движка.

**Включает:** `CURSOR_API_KEY` в секретах сервера; явная передача ключа в SDK/CLI;
изоляция воркспейса без write-токенов в env агента.

## Альтернативы

| Вариант | Почему отклонён как базовый путь |
| --- | --- |
| Запрет egress; только on-prem LLM | Высокая стоимость и срок; нет готового стека |
| Ревью только по diff в промпте без полного контекста repo | Слабее качество; агент не открывает файлы локально |
| Cloud agents по умолчанию | Self-hosted GitLab в приватной сети; усиленный egress |
| Обфускация/урезание кода перед отправкой | Ломает качество ревью; сложно автоматизировать |
