# 001. Гексагональная архитектура (порты и адаптеры)

- Статус: Принято (Accepted)
- Дата: 2026-06
- Контекст-ссылки: [../overview.md](../overview.md), [../../01-concepts/overview.md](../../01-concepts/overview.md), [../../03-reference/ports.md](../../03-reference/ports.md)

## Контекст

Mira интегрируется с несколькими внешними системами: self-hosted GitLab, Kaiten,
Cursor (CLI/SDK/cloud). Требование **G4** и **NFR-10** — гибко менять движок ревью,
VCS-провайдер и трекер задач без переписывания пайплайна. При этом ядро должно
оставаться тестируемым без сети и не «знать» про конкретные API.

## Решение

Применяем **гексагональную архитектуру** (ports & adapters):

- **`core`** — домен, оркестрация, политика, резолвер связей; зависит только от
  **портов** (интерфейсов: `VcsReader`, `TaskTracker`, `ReviewEngine`, `Publisher`,
  `StateStore`, `Queue` и т.д.).
- **`adapters`** — реализации портов под GitLab, Kaiten, Cursor CLI/SDK, SQLite,
  in-process queue.
- **`entrypoints`** — composition root: связывают `core` + адаптеры по конфигу и
  поднимают процессы (`api`, `worker`, `poller`, `cli`).

**Главный инвариант:** зависимости направлены **внутрь, к ядру**. `core` не импортирует
GitLab, Kaiten или Cursor — только типы домена и контракты портов.

## Последствия

**Плюсы:**

- Смена `CliHeadlessEngine` → `SdkLocalEngine` или другого VCS — замена адаптера,
  пайплайн не трогаем.
- Unit-тесты ядра на фейковых портах — быстрые и детерминированные.
- Границы модулей готовы к выделению в packages при росте (см.
  [003-modular-monolith-roles.md](./003-modular-monolith-roles.md)).

**Минусы:**

- Больше слоёв и файлов, чем у «монолита с прямыми HTTP-вызовами».
- Composition root должен быть единственным местом связывания — иначе границы
  размываются.

**Включает:** возможность подменить любой адаптер (второй GitLab-инстанс, другой
трекер, cloud-движок) без изменения `core/orchestrator`.

## Альтернативы

| Вариант | Почему отклонён |
| --- | --- |
| Монолит с прямыми вызовами GitLab/Kaiten API из воркера | Жёсткая связность; смена движка или VCS = переписывание пайплайна |
| Микросервисы по интеграциям | Оверкилл на текущем масштабе; усложняет деплой одного сервера |
| Plugin-система с динамической загрузкой | Избыточна; достаточно статической композиции в `entrypoints/main.ts` |
