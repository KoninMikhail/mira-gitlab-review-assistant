# 020. Пул Cursor API-ключей с failover

- Статус: Принято (Accepted)
- Дата: 2026-09
- Контекст-ссылки: [019-live-secret-rotation.md](./019-live-secret-rotation.md),
  [../../03-reference/environment.md](../../03-reference/environment.md)

## Контекст

Один `CURSOR_API_KEY` часто протухает или упирается в лимит. Рестарт и ручная
смена ключа уже закрыты ADR 019; нужен запасной ключ **на том же процессе**,
чтобы ревью продолжилось.

## Решение

`CURSOR_API_KEY` — пул: несколько значений через запятую / `;` / перевод строки
(или JSON-массив в `PUT /admin/secrets`). Адаптер `KeyFailoverEngine` пробует
ключи по кругу, начиная с последнего успешного.

Следующий ключ — только если текущий прогон выглядит как мёртвый ключ
(non-zero exit `cursor-agent`, auth/quota). Таймаут и невалидный JSON findings
**не** крутят пул: это не «ключ недоступен», а дорого / ключ уже сработал.

GitLab/Kaiten остаются одним токеном.

## Альтернативы

| Вариант | Почему не выбран |
| --- | --- |
| Failover на любую ошибку, включая timeout | N × 10 мин на одно ревью |
| Отдельная `CURSOR_API_KEYS` | Лишний env при том же смысле |
| Параллельный вызов всех ключей | Двойная оплата и гонки записи findings |

## Последствия

- Один ключ в env — поведение как раньше.
- В логах `cursor.keys.count` и `engine.key.failover` (индекс, не значение).
