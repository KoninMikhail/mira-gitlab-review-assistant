# 009. Dry-run publisher на фазе MVP

- Статус: Принято (Accepted)
- Дата: 2026-06
- Контекст-ссылки: [../../01-concepts/overview.md](../../01-concepts/overview.md), [../../01-concepts/roadmap.md](../../01-concepts/roadmap.md), [008-kaiten-read-only.md](./008-kaiten-read-only.md)

## Контекст

Полный цикл Mira — от триггера до **публикации** структурированных находок в MR
(сводный комментарий + inline-дискуссии). На фазе 1:

- GitLab MCP **read-only** — нет write в MR;
- выделенный **bot-аккаунт GitLab** и REST write — фаза 2 (Q-1);
- Kaiten write под личным токеном **запрещён** (см.
  [008-kaiten-read-only.md](./008-kaiten-read-only.md)).

При этом пайплайн ревью (контекст → движок → нормализация → state store) должен
работать end-to-end и давать наблюдаемый результат для отладки и метрик.

## Решение

**Publisher на фазе 1 — dry-run:** реализация `LogPublisher`
(`src/adapters/publisher/log/`), реализующая порт `Publisher`.

Поведение:

- эмитирует структурированный лог: `review.summary`, `review.finding`,
  `review.requirement`, `review.degraded`;
- поле `dry_run: true` в контексте логера;
- **не пишет** в GitLab MR и **не пишет** в карточку Kaiten.

Порт `Publisher` сохраняется — на фазе 2 подмена на `GitLabPublisher` (REST под
bot-аккаунтом) без изменения оркестратора. Kaiten write-back — отдельный адаптер
после бот-токена (фаза 3+).

Принцип сохраняется: **публикует Publisher, не агент** — детерминированная
идемпотентная запись, когда write появится.

## Последствия

**Плюсы:**

- MVP проверяет весь пайплайн кроме внешней записи;
- нулевой риск спама в MR при отладке;
- не требует bot-токена GitLab для фазы 1;
- логи пригодны для метрик и инспекции находок.

**Минусы:**

- Разработчики не видят ревью в MR до фазы 2;
- нужна дисциплина смотреть логи/observability вместо комментариев MR.

**Включает:** критерий выхода фазы 1 — «стабильно крутится, не дублирует, метрики
идут»; публикация в MR — критерий фазы 2.

## Альтернативы

| Вариант | Почему отклонён для MVP |
| --- | --- |
| Сразу REST write в GitLab | Нет bot-аккаунта и прав на пилотные репо (блокер P2) |
| Write сводки в Kaiten под личным токеном | Запрещено rule и ADR-008 |
| Публикация через агента (MCP write) | Недетерминированно; ломает идемпотентность |
| Stdout без структурированного лога | Хуже для observability и автоматических метрик |
| Отложить Publisher entirely | Ломает контракт пайплайна; сложнее тестировать end-to-end |
