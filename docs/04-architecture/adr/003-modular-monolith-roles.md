# 003. Модульный монолит и процессы-роли

- Статус: Принято (Accepted)
- Дата: 2026-06
- Контекст-ссылки: [../overview.md](../overview.md), [../../05-operations/deployment.md](../../05-operations/deployment.md), [001-hexagonal-architecture.md](./001-hexagonal-architecture.md)

## Контекст

Mira разворачивается на **одном выделенном сервере**, команда небольшая. Нужна
структура репозитория и деплоя, которая даёт модульность (смена адаптеров) без
операционной сложности микросервисов или multi-package monorepo.

## Решение

**Модульный монолит** в одном репозитории `mira-review-bot`:

- **один деплоимый артефакт** — один Docker-образ;
- **несколько процессов-ролей** из этого образа, выбор через переменную `ROLE`:
  - `api` — webhook receiver, healthz (фаза 2+);
  - `poller` — опрос GitLab (может жить внутри `api` или отдельно);
  - `worker` — консьюмер очереди, исполнение ревью;
  - `all` — совмещённый режим для простого деплоя;
  - `cli` — ручной прогон / PoC без очереди.
- **внутри образа** — чёткие модули по слоям гексагона: `core/`, `adapters/`,
  `entrypoints/`, `config/`.

Workspaces / multi-package monorepo **не вводим**, пока не появится собственный
GitLab write-MCP или переиспользуемая библиотека.

## Последствия

**Плюсы:**

- Простая сборка, отладка и эксплуатация на одном сервере;
- `worker` масштабируется репликами; `api` — за балансировщиком;
- тот же код ядра в `cli` для PoC и отладки;
- границы `core`/`adapters`/`entrypoints` позволяют позже «вырезать» packages без
  переписывания логики.

**Минусы:**

- Все роли делят одну версию образа — нельзя независимо релизить только poller;
- один процесс с `ROLE=all` не даёт независимого масштабирования ingress и worker.

**Включает:** `deploy/docker-compose.yml` с сервисами `api` и `worker` из одного
образа; composition root в `entrypoints/main.ts`.

## Альтернативы

| Вариант | Почему отклонён |
| --- | --- |
| Multi-package monorepo (pnpm workspaces) | Нет переиспользуемых пакетов сейчас; лишняя сложность |
| Полирепозиторий микросервисов | Независимые релизы не нужны; оверкилл для одной команды |
| Отдельные репозитории на каждый адаптер | Разрывает гексагон и усложняет сквозные изменения контрактов |
