# Java / JVM — фокус ревью

Цель ревью — двигать код к enterprise-уровню (надёжность, безопасность,
тестируемость, явные контракты, безопасные дефолты), а **не** закреплять текущую
архитектуру — она будет переписана. Отмечай долгоживущие практики. Хвали удачные
решения; замечания подавай как возможность улучшить, с понятной выгодой и
небольшим посильным фиксом.

Типичный стек (примеры, не требование): Java 17 + Spring Boot 3.x, JPA/Hibernate,
PostgreSQL + Liquibase, Feign/WebClient, Keycloak/OAuth2, MinIO. Привязывайся к
принципу, технологию упоминай как пример.

## Безопасность и авторизация

- **Безопасные дефолты доступа**: новый endpoint не должен оказаться открытым по
  умолчанию. Доступ задаётся явно (security filter chain / method security), а не
  широким `permitAll`. Каждое исключение из правила — осознанно и обосновано.
- Роли/authority из токена мапятся корректно при любом числе ролей; не теряй
  authorities на граничных случаях.
- Callback/webhook/SSE-эндпоинты тоже защищены (allowlist / подпись / mTLS / ключ).
- SSRF: не дёргай произвольные URL из пользовательского ввода без allowlist,
  таймаутов и лимита размера ответа.
- Криптография: уникальные IV/nonce, безопасное хранение и ротация ключей,
  `SecureRandom` для токенов; никогда не логируй plaintext/секреты.
- Внешние интеграции (Telegram/боты и пр.): экранирование форматирования, retry/backoff
  и rate-limit под ограничения API; не глотай ошибки в `log.*` без проброса/учёта.

## Интеграции и ресурсы

- Клиенты внешних сервисов: явные таймауты, обработка ошибок (error decoders),
  идемпотентность при retry.
- Загрузка файлов: разумные лимиты размера; потоки/`InputStream` — через
  try-with-resources.
- Долгоживущие соединения/эмиттеры (SSE и т.п.): таймаут, очистка в
  `onCompletion`/`onTimeout`, отсутствие утечек в реестрах.

## Spring / JPA / миграции

- Конструкторная инъекция вместо field injection; корректные границы
  `@Transactional` (не на private/самовызове), осознанный rollback.
- N+1 и `LAZY` вне сессии; пагинация для коллекций; индексы под фактические фильтры.
- Миграции схемы — обратносовместимые; никаких хардкод-кредов в конфигах/миграциях,
  только подстановка из env.
- Согласованность DTO↔entity (мапперы); корректные annotation processors.

## Корректность и исключения

- NPE-риски: разыменование без проверки, `Optional.get()` без `isPresent`.
- Согласованные `equals`/`hashCode`; сравнение строк через `equals`, не `==`.
- Деньги/точность — `BigDecimal`, не `float`/`double`.
- Не глотай и не «перекрывай» исключения (`catch (Exception e) {}`, оборачивание в
  голый `RuntimeException`, маскировка ошибки кодом ответа) — сохраняй контекст.
- Разделяемое мутабельное состояние без синхронизации; блокирующие вызовы в
  реактивных цепочках.

## Качество

- Параметризованные запросы вместо конкатенации в SQL/JPQL; никакой десериализации
  недоверенных данных.
- Поощряй тесты на новую логику (`@SpringBootTest`/repository/unit), особенно там,
  где CI их не требует, — это снижает регресс при будущем рефакторинге.
