# Frontend (React / Vue / SPA) — фокус ревью

В отличие от бэкенда (который будет переписан), на фронтенде уже **сложилась
здоровая архитектура — её нужно последовательно развивать и удерживать
консистентность**, постепенно готовя почву к микрофронтендам. Поэтому здесь ревью
поощряет соответствие сложившимся конвенциям и их аккуратную эволюцию, а не
переизобретение. Хвали удачные решения; замечания подавай как возможность
улучшить — с понятной выгодой и небольшим посильным фиксом.

Сложившийся стек: React + Vite SPA, **Effector (+ patronum)** как стейт-менеджер,
типизированный HTTP-слой (**Farfetched + Axios + Zod-контракты**), формы на
**react-hook-form + zodResolver**, UI-кит (HeroUI) + Tailwind, i18n (i18next),
архитектура по слоям (FSD), embed/postMessage-интеграции (в т.ч. Superset).

## Архитектура и состояние (держим и развиваем)

- Соблюдай слои FSD и направление зависимостей; новый код кладётся в правильный
  слой, бизнес-логика — вне компонентов. Это и есть подготовка к микрофронтендам:
  чистые границы и явные контракты модулей.
- Стейт — на Effector: связывание через `sample()`, command-style публичный API
  моделей; следи за утечками подписок и нестабильными ссылками. Не тащи параллельно
  второй подход к стейту без причины — консистентность важнее.
- Производные данные — через `combine`/вычисление, не дублируй в сторах.
- Persist только UI-предпочтений (effector-storage/local); чувствительные/доменные
  данные в localStorage не храним.

## Контракты данных

- HTTP — через Farfetched + Zod-контракты; типы ответа подтверждены схемой и
  совпадают с бэкендом. Обработаны состояния загрузки/ошибки/пустого списка и
  сетевые сбои.
- Формы — react-hook-form + zodResolver; ошибки прокидываются единообразно
  (errors-bus → `setError`). Держи единый стиль валидации; следи за дрейфом версий
  Zod между частями кодовой базы.

## Безопасность

- Токены — в cookie (httpOnly/SameSite/secure, доменный префикс), не в localStorage;
  обновление через single-flight refresh (mutex), без гонок; учитывай миграцию legacy-cookie.
- XSS: `dangerouslySetInnerHTML` / `v-html` только с санитизированными данными.
- postMessage / OAuth tab-flow / Superset embed: проверяй `origin`, `source`,
  `state`; очищай listeners; защита от double-submit. Гостевые токены/секреты —
  только через бэкенд, не в клиентском коде.
- Открытые редиректы; `target="_blank"` без `rel="noopener"`.

## Качество, UX, производительность

- Хуки: правила хуков, корректные зависимости эффектов (`exhaustive-deps`), очистка
  подписок/таймеров/listeners.
- Строки — через i18n (`locale/*.json`), не inline.
- UI: HeroUI + Tailwind; при переносе компонентов и апгрейдах учитывай breaking
  changes мажорных версий (в кодовой базе есть разнобой версий — выравнивай, а не
  закрепляй).
- Доступность: семантика, labels/alt, клавиатура, контраст.
- Мемоизация тяжёлых вычислений; виртуализация длинных списков; code-splitting в
  горячих местах.
- `VITE_*` — build-time переменные: изменение требует пересборки, не рантайм-подмены.
- Запрет «немой» типизации (`any`); поощряй тесты (vitest + MSW, e2e) на
  нетривиальную логику/состояние — они страхуют развитие архитектуры до микрофронтендов.
